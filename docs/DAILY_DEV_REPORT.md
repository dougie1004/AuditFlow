# AuditFlow Daily DEV Report (2026-02-08 ~ 2026-02-09)

## 🎯 오늘의 목표: AI 통찰과 감사 워크플로우의 완전한 연결 (Loop Closure)
AI가 찾아낸 '의심(Insight)'을 단순한 알림으로 끝내지 않고, 실제 감사인이 '조치(Action)'할 수 있는 정식 **'심사 대기열(Review Queue)'**로 연결하는 파이프라인을 완성했습니다. 또한, 데이터 휘발성 문제를 해결하여 연속적인 감사 업무가 가능하도록 인프라를 안정화했습니다.

---

## ✅ 주요 성과 (Achievements)

### 1. AI와 감사 워크플로우 연결 (The Missing Link)
- **현상**: AI가 리스크를 탐지해도 감사인이 이를 정식 이슈로 등록할 방법이 없어 프로세스가 단절됨.
- **조치**: 
    - 백엔드에 `promote_risk_v2` 커맨드 구현 (AI 신호 -> 정식 리뷰 항목 승격).
    - 프론트엔드에 **[이슈 등록]** 버튼 추가.
- **결과**: 클릭 한 번으로 AI의 발견 사항이 '이슈 검토 목록'으로 이동하여, 승인/반려/소명 요청의 대상이 됨.

### 2. 세션 및 데이터 영속성 확보 (Persistence)
- **현상**: 앱을 재시작할 때마다 세션과 리뷰 항목이 초기화되어(Dev Mode), "No Active Session" 상태가 반복됨.
- **조치**: `database.rs`의 무조건적인 테이블 삭제(DROP TABLE) 로직 제거.
- **결과**: 감사 세션과 작업 내역이 영구 보존되어, 실제 업무 환경과 동일한 경험 제공.

### 3. 데이터 스키마 마이그레이션 (Schema Upgrade)
- **현상**: 리뷰 항목 ID가 `Integer`에서 `UUID(String)`로 변경되었으나, DB 스키마와 Rust 모델이 이를 따라가지 못해 목록이 비어 보이는 버그 발생.
- **조치**: 
    - 테이블명을 `review_item` -> `review_tasks`로 변경하여 `ID TEXT PRIMARY KEY` 스키마 강제 적용.
    - Rust `struct` 및 관련 쿼리 일괄 수정.
- **결과**: 데이터 불일치(Type Mismatch)로 인한 크래시 및 누락 문제 완전 해결.

# AuditFlow Daily DEV Report (2026-02-07) - Part 2: 데모 데이터 전략 고도화 및 심층 맥락 검증

## 🎯 오늘의 목표: '연출'을 넘어 '실무적 정직함'을 갖춘 데모 엔진 구축
단순히 범인을 찾는 '드라마' 중심의 데모 데이터에서 탈피하여, 규정의 경계선(Boundary)을 드러내고 시스템의 **'심층 맥락 분석(Deep Context)'** 능력을 증명하는 실질적인 검증 시스템을 구축했습니다.

---

## ✅ 주요 성과 (Achievements Supplement)

### 1. 데모 데이터 전략의 패러다임 전환 (Narrative → Structure)
- **현상**: 시스템의 우수성을 보여주기 위해 자극적이고 명백한 '범죄 시나리오'를 주입하던 관행.
- **조치**: **'경계 조건(Boundary Conditions)'** 중심의 데이터셋으로 전면 개편.
    - 엔진이 "이것은 위반이다"라고 소리치는 게 아니라, "이 지점은 판단이 모호하니 침묵하거나 질문해야 한다"는 것을 증명하는 것이 최우선 목표.
- **결과**: AuditFlow가 범인 검거기가 아닌, 전문가의 판단을 돕는 정교한 '도구'임을 명확히 함.

### 2. 비현실적 '수치 경쟁' 폐기 (Agnostic vs Mass)
- **현상**: "1만 건을 수초 만에 처리한다"는 방식의 과시적 기술력 강조.
- **조치**: 실무적 리얼리즘(Professional Realism)에 따라 비현실적인 대량 처리 로직 삭제.
    - **'심층 맥락 검증(Deep Context Validation)'** 모드로 전환하여, 단 5개의 사례를 처리하더라도 그 깊이를 보여주는 데 집중.
- **결과**: "구글도, OpenAI도 못 하는 일을 우리만 순식간에 한다"는 모순을 제거하고, 고난도 분석에 필요한 '경건한 시간'과 '투명한 논리 전개'를 시스템 리듬에 반영.

### 3. 고밀도 교차 검증 시나리오 구현 (Cross-Silo Verification)
- **현상**: 단일 데이터 소스(결제 내역 등)에만 의존하던 단순 분석.
- **조치**: 서로 다른 사일로(Silo) 간의 데이터를 대조해야만 답이 나오는 5가지 고정밀 시나리오 주입.
    - **예시**: 인사팀 외근 일지와 법인카드 승인 시각 대조, OCR 영수증 데이터와 자금 결제처 원본 데이터 정밀 매핑, 소유 구조 추적을 통한 자금 우회 가능성 분석 등.
- **결과**: 다차원적 데이터 정합성을 파악하는 AuditFlow만의 독보적 지능을 증명.

### 4. 중립성 엔진 Baseline 확립 (Neutrality Baseline)
- **현상**: 모의 데이터 주입 시 시스템이 반드시 '위반'을 찾아내야 한다는 강박.
- **조치**: **'Agnostic Data(기대 결과가 없는 데이터)'** 개념 도입.
    - 엔진이 '말하면 안 되는 순간'을 정의하고, 노이즈 데이터 속에서도 평정심(Silence)을 유지하는지 검증하는 `Neutrality Calibration` 기능 구현.
- **결과**: AI의 확증 편향을 차단하고 시스템의 중립적 신뢰성(Trust Baseline) 확보.

# AuditFlow Daily DEV Report (2026-02-07) - Part 1

## 🎯 오늘의 목표: 하이브리드 스코어링 도입 및 AI 중립성 헌법 강화 (Choice 2 Implementation)
AuditFlow의 인제스션 엔진과 스코어링 체계를 전면 개편하여, AI의 주관적 판단을 억제하고 통계적 근거와 물리적 규칙이 결합된 **'정직한 관측 시스템'**으로 전환하는 작업을 완료했습니다.

---

## ✅ 주요 성과 (Achievements)

### 1. 하이브리드 이상치 스코어링 엔진 v1.0 (Hybrid Scoring)
- **현상**: AI의 직관(Semantic)에만 의존하여 산정되던 이상치 점수의 신뢰성 문제 해결.
- **조치**: 세 가지 지표의 가중합 체계 도입.
    - **S-Score (Semantic, 40%)**: AI가 분석한 목적과 가중점 간의 맥락적 괴리도.
    - **V-Score (Value, 40%)**: 배치 데이터 내 금액 분포 기반의 통계적 이상치(Z-Score).
    - **C-Score (Context, 20%)**: 주말/심야 결제, 제한 업종 키워드 등 확정적 팩트 가산점.
- **결과**: 금액이 평범하고 업종이 클린한 경우 AI가 독단적으로 높은 점수를 줄 수 없는 구조 확립.

### 2. AI 헌법 제7조 명문화: '의미 보완 본능 억제'
- **현상**: AI가 높은 점수를 부여한 후 이를 정당화하기 위해 "조사 권고" 등 주관적 서사를 덧붙이던 '오버' 행위 차단.
- **조치**: 헌법에 "의미를 완성하려 하지 마라"는 조항 추가. AI는 이제 [숫자 + 기계적 사실]만 나열하며, 어떤 형태의 권고 문장도 생성할 수 없음.

### 3. 데이터 인제스션 필터 강화 (Constitutional Filter)
- **현상**: 마스터 데이터(vendor_master.csv)가 거래 내역으로 오인되어 대시보드에 '금액 0'인 노이즈가 대량 발생하던 문제.
- **조치**: 
    - 파일명 스캔(`master` 키워드) 및 컬럼 내용 검사(금액 관련 헤더 유무)를 통해 비거래성 파일은 분석 대상에서 자동 제외.
    - 데이터 성격을 정직하게 규정하는 Manifesto 3.1 원칙 준수.

### 4. 시스템 전체 초기화 기능 고도화 (Full Reset)
- **현상**: DB 초기화 시 업로드된 파일 리스트와 프로젝트 정보가 남아있어 중복 데이터가 쌓이던 문제.
- **조치**: `debug_reset_inbox` 명령이 `audit_data`, `audit_projects` 테이블까지 모두 비우도록 수정하여 완전한 'Zero-Base' 초기화 실현.

# AuditFlow Daily DEV Report (2026-02-02)

## 🎯 오늘의 목표: 심사 규정 고도화 및 시스템 정합성 강화 (Phase 4.2 Refinement)
AuditFlow의 판정 엔진이 단순히 '수상함'을 탐지하는 것을 넘어, **"왜 심사를 완료할 수 없는가(Unclassified)"**를 명확히 정의하고, 감사인의 전문적 판단과 시스템 규정 사이의 균형을 UI에 정밀하게 투영하는 작업을 진행했습니다.

---

## ✅ 주요 성과 (Achievements)

### 1. 심사 미분류 사유 코드화 (Reason Codification)
- **현상**: 규칙에 걸리지 않는 데이터가 단순히 '기각'되거나 '누락'되던 문제 해결.
- **조치**: `AdjudicationOutcome::Unclassified` 도입 및 세부 사유(`NoApplicableRule`, `InsufficientFields`) 정의. 현재 심사 기준의 한계를 데이터로 축적할 수 있는 기반 마련.

### 2. 동적 맥락 인식 및 오진 수정 (Dynamic Reasoning)
- **현상**: 쿠팡에서 노트북을 사도 "식대 범위 상회"라고 표기되던 엔진의 게으름 교정.
- **조치**: 가맹점(쿠팡, 하이마트, 호텔 등)과 금액을 대조하여 사유를 동적으로 생성. 이제 노트북 구매 시 **"고액 자산성 물품 구매 패턴 관측"**으로 정확히 출력됨.

### 3. 규정 중심의 UI 개정 (Regulation-First UI)
- **현상**: 높은 이상치(80% 이상)에 빨간색/깜빡임을 사용하여 AI를 '심사 주체'처럼 보이게 했던 UX 오류 수정.
- **조치**: 
    - AI 점수를 무채색(Slate)으로 변경하여 **'참고 지표(Witness)'**임을 명시.
    - **검토 결과(Conclusion) → 심사 근거(Reasoning) → 참고 정보(AI Score)**의 정보 위계 확립.
    - `Escalation Eligibility` 대신 **`Investigation Status`** 등 현업 지향적 용어로 정체성 확립.

### 4. 엔진 멱등성 및 전수 재심사 (Idempotency & Replay)
- **현상**: 심사를 재실행할 때 기존 로그와 중복되거나, 이미 완료된 건이 업데이트되지 않던 문제.
- **조치**: 
    - 심사 시작 시 기존 로그 `DELETE` 후 `INSERT` 하도록 로직 변경.
    - [심사 실행] 버튼 클릭 시 `Pending` 뿐만 아니라 `Processed` 데이터까지 전수 다시 읽어 최신 로직 적용(Full Replay).

- **통계 쿼리 보정**: 메인 대시보드 및 리포트에서 `Unclassified` 상태가 누락되지 않고 정확히 카운트되도록 SQL 쿼리 최신화.
